Process

How a ticket becomes a shipped design at Huma. Five steps, run with Claude Code and agents I built for it, and one rule behind all of them: nothing goes on screen unless I can point to the line that asks for it.

Read the ticket the way an engineer will

The audit agent reads the ticket, every PRD it depends on, the prototypes already shipped and the Figma files, in that order of authority. It returns a change list in which every addition, change and removal cites the line that requires it.

In
A Jira ticket
Out
A cited change list and before/after sheets

RuleIf I can’t cite it, it doesn’t ship.

Change list5 items · 4 cited · 1 open
  • AddEmpty state when no slots are freePRD · Screens and states
  • ModifyConfirm button labelAcceptance criterion 2
  • RemoveDraft status chipNo PRD line found
  • KeepConsent sentence, word for wordPRD · What must be true
  • DecideRetry limit after a failed sendGap · sent to step 02

When the PRD is silent, make the gap visible

The decision helper searches the PRD and its decision notes first, then NHS England and ICO guidance, then how peer products behave. It either finds the answer that already exists, or lays out real options with a recommendation.

In
A question the documents don’t answer
Out
A decision with a named owner, recorded in a pull request

RuleA recorded decision beats a confident guess in a wireframe.

Open questionExample

How many times can a failed reminder be resent?

Anything touching consent, patient safety or the patient record goes to the product owner.

Design in code, on the real design system

I build the screens in HTML with Claude Code, from the design system’s own components and tokens rather than values typed from memory. Every state the PRD names gets built: empty, loading, error and limits, not just the happy path.

In
The change list and its decisions
Out
A live prototype with every state

RuleA value I retyped is a value I invented.

reminders.html
DefaultEmptySend failedLimit reached
Reminder not sentTry again, or call the patient.

<Button variant="primary"> · var(--space-4) · from the library, never retyped

Hand engineers only what the story touched

The handoff slicer cuts the story’s screens out of the full prototype into one standalone HTML file. A control card on top switches between every named scenario, so each state is one click away and the file opens anywhere, offline.

In
The prototype and the handoff notes
Out
One file per handoff, every state reachable

RuleCut, don’t build. A state the prototype lacks is listed as not drawn, never faked.

Not drawn (1): bulk resend. The prototype doesn’t build it; the handoff says it should.

Publish, review, then walk the team through it

The deliverable goes into the design repo under the PRD, story and ticket it belongs to, through a branch and a pull request. Then I present it from a five-minute script built from the latest output and its decisions, with open questions listed, not buried.

In
The prototype and the handoff file
Out
A merged pull request and a team walkthrough

RuleA decision isn’t proof the build has it. Check the screen before saying it’s there.
